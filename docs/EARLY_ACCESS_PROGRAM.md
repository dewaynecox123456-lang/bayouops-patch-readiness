# BayouOps EarlyAccess Program

## 1. Purpose

The BayouOps EarlyAccess program exists to:

- validate operational workflows
- improve release quality
- gather real operator feedback
- test release packaging and reporting
- identify usability and documentation gaps

EarlyAccess helps refine BayouOps before broader stable releases.

---

# 2. What EarlyAccess Means

EarlyAccess releases are functional but evolving.

These releases may include:

- experimental workflows
- evolving dashboards
- changing report formats
- release engineering improvements
- operational workflow refinements

EarlyAccess builds are intended for:

- labs
- demonstrations
- portfolio validation
- controlled operational testing
- operator feedback cycles

They are not positioned as production-certified enterprise platforms.

---

# 3. What Data Is Collected

BayouOps EarlyAccess may collect minimal licensing and usage metrics.

Collected data may include:

- registered name
- email address
- license identifier
- product version
- platform type
- last check-in timestamp
- total check-in count

This information is used only to:

- measure active usage
- improve release planning
- identify version adoption
- communicate important release updates

---

# 4. What Data Is NOT Collected

BayouOps does NOT intentionally collect:

- inventory contents
- hostnames
- IP addresses
- vulnerability findings
- generated reports
- operational notes
- exported dashboards
- customer environment data
- credentials
- internal infrastructure information

BayouOps is designed to remain operator-controlled and local-first.

---

# 5. Offline Behavior

BayouOps is designed to function locally without requiring constant internet access.

The platform should remain usable even when:

- disconnected from the internet
- isolated within lab environments
- used in restricted operational networks

Optional check-ins should not block normal operational workflows.

---

# 6. Update Model

BayouOps currently uses a manual-download update model.

The platform does not perform automatic in-place updates.

Operators remain responsible for:

- reviewing release notes
- downloading updated releases
- validating operational changes
- controlling deployment timing

This model favors predictability and operational safety.

---

# 7. Feedback Expectations

EarlyAccess participants are encouraged to provide:

- workflow feedback
- bug reports
- release issues
- usability observations
- documentation gaps
- operational improvement suggestions

Practical operator feedback is prioritized over feature hype.

---

# 8. Support Expectations

EarlyAccess support is best-effort.

Support may include:

- release clarification
- workflow guidance
- bug review
- documentation updates

Response times are not guaranteed.

---

# 9. Expiration / Renewal Model

EarlyAccess licenses may include expiration dates.

Expiration is intended to:

- encourage version refresh
- improve release consistency
- reduce outdated test environments
- support active feedback cycles

Renewals may be granted for continued testing participation.

---

# 10. Safety & Privacy Philosophy

BayouOps prioritizes:

- operator trust
- explainable behavior
- local control
- operational transparency
- minimal telemetry
- predictable workflows

The platform should never silently collect operational environment data or perform hidden remediation actions.
